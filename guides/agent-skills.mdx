Coding agents use TinyCloud through the `tinycloud` CLI. Its stable npm package ships
a `tinycloud-cli` skill that teaches the commands, authentication flows and
error codes for that exact release. The quickest setup is
[agents.tinycloud.xyz/onboarding](https://agents.tinycloud.xyz/onboarding): it
installs the CLI and skill and runs `tinycloud onboard`. The steps below do the
same by hand.

For ChatGPT, Claude app, Grok/GrokBot and WhatsApp/Instinct connection
qualifications, see [Choose your client](/cli/mcp#choose-your-client).
The shell instructions below apply to Claude Code, Codex and OpenCode
runtimes that can execute local commands, not every app bearing those names.

## Install the CLI and the `tinycloud-cli` skill

Use Node.js 22.20 or later. Prefer onboarding, which reuses a compatible
installed CLI rather than installing a second copy. For a fresh manual
installation, the stable CLI pin is 1.5.0; do not downgrade a compatible
newer installation.

### macOS and Linux

```bash
npm install --global @tinycloud/cli@1.5.0
TC="$(npm prefix --global)/bin/tc"      # avoids /usr/sbin/tc on Linux
VERSION="$("$TC" --version)"
npx --yes skills@1.7.0 add \
  "https://registry.npmjs.org/@tinycloud/cli/-/cli-${VERSION}.tgz" \
  --skill tinycloud-cli --global --copy --agent opencode codex claude-code --yes
```

This copies the skill for that CLI release into each client's skill directory,
for example `~/.claude/skills` for Claude Code, or `~/.agents/skills` for
OpenCode and Codex. Pass the agents you use; other agents use their own skills
folder. Start a new agent session and ask it to use `tinycloud-cli`.

<Warning>
On Linux, `tc` on the `PATH` often resolves to `/usr/sbin/tc`, the iproute2
traffic-control tool. Point agents at the CLI by absolute path, as above.
</Warning>

### Windows

Follow [Windows installation and PATH repair](/cli/overview#windows).
For a manual npm installation, resolve the Windows npm shim and install the
skill for that CLI's actual version in PowerShell:

```powershell
$TC = Join-Path (npm prefix --global) 'tinycloud.cmd'
$Version = (& $TC --version).Trim()
npx --yes skills@1.7.0 add "https://registry.npmjs.org/@tinycloud/cli/-/cli-$Version.tgz" --skill tinycloud-cli --global --copy --agent opencode codex claude-code --yes
```

If onboarding selected an existing CLI or the private installer, use that
reported executable as `$TC` instead. Do not install another copy just to
match this example.

## Check, update, and remove

```bash
"$TC" --version
npx --yes skills@1.7.0 list --global
```

Keep the skill and CLI release aligned. To update, explicitly upgrade the
selected installation and rerun `skills add` with that version's tarball URL;
a pinned URL never updates itself. Preserve locally modified skills.

```bash
npx --yes skills@1.7.0 remove tinycloud-cli --global --agent opencode codex claude-code --yes
npm uninstall --global @tinycloud/cli
```

Removing the skill or the CLI does not delete TinyCloud profiles or revoke any
access an agent was granted. Revoke those with `tc delegation revoke` or from
the account app.

## Give the agent access

The agent runs `tinycloud onboard` once and reuses its grants. If a task needs
more access, request only the missing permissions with
`tinycloud auth request ... --grant --no-popup --expiry 30d`. Send the complete
short URL on its own line and keep the command running; it retrieves approval
automatically. After interruption, rerun the same command and profile.
Explicit `--paste` selects the older long-link, manual-code fallback.

| Task | How the agent gets access |
|---|---|
| Explore and edit app data | Included in `tinycloud onboard`; see [Access and explore my TinyCloud](/guides/access-and-explore-my-tinycloud) |
| Publish Share links | A dedicated `publisher` profile: `tinycloud --profile publisher auth login --method openkey --no-popup --manifest builtin:share-publishing --expiry 30d`; see [Share files](/cli/share) |
| Read named API keys | A `secrets` manifest on its own profile; see [Secrets](/cli/secrets#give-an-agent-read-access-to-a-secret) |

## App skill packs

App skill packs build on `tinycloud-cli` for one job and publish their own CLI
requirements. The packs below are in
[TinyCloudLabs/prompts](https://github.com/TinyCloudLabs/prompts), currently in
preview:

- **`tc-publish`** publishes a document or HTML page and returns an owner-only
  or public Share link.
- **`tc-secrets`** reads API keys the owner keeps in Secret Manager, without
  the values passing through chat.

Install a pack by copying its directory into the agent's skill path, and follow
its `QUICKSTART.md` for the operator settings it expects. Packs never install
software themselves; if the CLI is too old they stop and say so.
